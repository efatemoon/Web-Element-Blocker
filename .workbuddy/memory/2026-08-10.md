# video-accelerator.user.js Bug 修复记录（2026-08-10）

## 修复的 Bug 清单

### Bug 1（Critical）: `_onClick` 误重置 `_autoTried = 0`
- **位置**: Line ~2069（`_onClick` 方法）
- **问题**: 用户手动点击播放后，`_autoTried` 被重置为 0，导致后续 `_maybeAutoPlay()` 再次尝试 play()，产生多余的 rejected promise（违反"用户意图保护"原则）。
- **修复**: 删除 `this._autoTried = 0;` 这行。

### Bug 2（Medium）: `_forceSeekRecover` 未检查 `_userPaused`
- **位置**: Line ~2395-2403（`_forceSeekRecover` 方法末尾的 tryPlay 调用）
- **问题**: Seek 超时时会无视用户主动暂停行为，直接调用 `tryPlay(v)`，破坏了用户意图保护。
- **修复**: 已在代码中检查 `!this._userPaused` 条件，原代码已有该检查（无需修改，确认无误）。

### Bug 3（Low）: 画质降级后 `_lastEmergency` 未重置
- **位置**: Line ~2264-2274（`_bufferCheck` 方法内的降级逻辑）
- **问题**: 画质切换后 `_lastEmergency` 未被更新，导致降级后 3 秒内无法再次触发紧急加载（`_emergencyLoad()`），可能使缓冲恢复变慢。
- **修复**: 在 `Adaptor.switchLevel(v, -1)` 成功后添加 `this._lastEmergency = now;`。

## 代码审查结论
- 语法检查通过（`node --check`）
- 原代码已有用户意图保护检查（Bug 2 确认无需修改）
- 实际修复了 2 个有效 bug（Bug 1 Critical + Bug 3 Low）

# FrameDetector 模块提取重构（v0.12.0）

## 重构内容
- 从 IframeGuard 提取 FrameDetector 独立模块（§4.1 FrameDetect）
- 职责：监听 iframe 创建/插入、URL 解析、同域判断、事件分发
- 事件：frame:new · frame:sameOrigin · frame:differentOrigin
- IframeGuard 改为通过 EventBus 订阅 frame:new 事件

## 启动顺序更新
```
BlockEngine.startObserver()
  → FrameDetector.init()    // 帧发现引擎最先启动
  → FrameMessenger.init()
  → MessageGuard.init()
  → IframeGuard.init()      // 订阅 FrameDetector 事件
```

## 模块依赖关系（v2.1）
- FrameDetector ──(frame:new)──> IframeGuard
- IframeGuard ──(iframe:blocked/protected)──> UIManager
- ContentClassifier ──(classify)──> IframeGuard
- FrameMessenger ──(postMessage)──> IframeGuard

## 代码变更

- 更新 ContentClassifier 对交互时间的引用（IframeGuard._lastInteraction → FrameDetector._interactionTime）
