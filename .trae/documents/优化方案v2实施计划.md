## 实施步骤（按依赖顺序）

### Step A — Item 1：AdScorerLR 向量化（Chapter 3）
位置：`AdScorerLR` 类（约 1610-1693 行）。
- `weights` 改为 `Float32Array([2.5,2.8,1.8,2.0,2.2,1.5,2.0])`（6 正向 + entropy 索引 6）。
- 新增 `keywordMap = new Map([['ad',0],['ads',1],['analytics',2],['track',3],['banner',4],['pixel',5]])`，`ENTROPY_INDEX=6`。
- 移除负向权重（js/api/tampermonkey）——与 hostname-only 改动耦合，基础设施由 bias+阈值+safCDN 保护。
- `getEntropy` 改用 `Uint8Array(256)` + `charCodeAt`。
- `evaluate`：仅 `url.hostname` 分词（去掉 pathname）；`z<=0` 返回 0；熵阈值 3.6、bonus 2.0。
- `shouldAutoBlock` 不变（同源+safCDN 豁免，阈值保持 85——静默自动拦截需保守）。
- 唯一调用点 1712 行无需改动。

### Step B — Item 4：网络层倒排索引（Chapter 2）
- 新增 `PathInvertedIndex` 类（置于 BlockEngine 前）：`build(patterns)` 提取每条 pattern 最长 ≥4 字符 token 建 `Map<token,indices>`，无 ≥4 token 的进 fallback 线性表；`test(url)` 分词查索引得候选集，仅测试候选 + fallback。
- BlockEngine 新增 `static _cachedPathIndex = null;`，**必须在 `invalidateCache`（约 406 行）一并置 null**（最易漏的 Bug）。
- `isUrlBlocked`（约 445 行）path 匹配改用 `_cachedPathIndex.test()`，懒构建（同 `getPathMatcher` 数据源）。
- `getPathMatcher()`（合并正则）保留，供 `scanAndBlockDynamic` 的 `.exec()` 提取匹配串日志使用。
- Bloom Filter 无代码，由 `AdScorerLR.safeCDNs` Set 作零误判快速放行等价物。

### Step C — Item 2：MurmurHash3 模糊拓扑 + 旧规则迁移（Chapter 4）
- BlockEngine 新增 `static murmur32(str)`（Math.imul，MurmurHash3 x86 32-bit）。
- 重写 `generateTopologyFingerprint`（1363-1386）：沿父链收集 `tag(classNameLength)`，深度<5，到 `document.body` 或 parent 为 null 停（shadow 安全），拼接后 `murmur32` 返回 hex。
- `applyTopologyRules`（1392）不变（Set 比对仍有效）。
- **旧规则迁移**：StorageManager 构造函数检测 `pro_blocker_topo_hash_version`，<1 则扫描 `structBlocks` 删除匹配旧格式 `/^\w+\|p\[/` 的 topoHash 规则，置 version=1，console 提示用户重新框选。优于静默失效。

### Step D — Item 3：Constructable Stylesheets（Chapter 5.1）
- BlockEngine 新增 `static _constructableSheet = null;`。
- `applyCSSRules`（634-716）：指纹跳过（695）之后、`<style>` 创建（675）之前，插入 constructable 分支：feature-detect `'CSSStyleSheet' in window && 'adoptedStyleSheets' in document`；懒建 `_constructableSheet=new CSSStyleSheet()`；`try { replaceSync(cssText); document.adoptedStyleSheets=[...,sheet]; } catch { 落到 <style>+insertRule }`。
- 空选择器早清（687-691）：constructable 走 `replaceSync('')` + 移除 adoptedStyleSheet。
- `<style>`+insertRule 路径完整保留作降级（铁律3）。
- 指纹跳过、`invalidateCache` 逻辑不变；sheet 实例复用不重建。
- `injectHighlightStyle` 不动（独立 style，非热路径）。

### Step E — Item 5：自动化泛化引擎（Chapter 1 + 6.2）
- 新增 `DomainGeneralizer.extractOptimalDomains(domains)`：反向基数树，节点子数 ≥3 收敛为 `*.base`（存储 base 域名，如 `network.com`，因 hostnameBlocked 父域上探已覆盖子域）。
- 新增 `PathGeneralizer.extractOptimalPattern(paths)`：MSA 按 `/` 对齐，相同 token 保留、不同置 `*`；有效字符<8 或通配符>2 或结果为 `/*` 则废弃入 fused。
- 新增 `AutoGeneralizer`：`onDomainRuleAdded(domain)`、`onPathRuleAdded(pattern,domain)`、`run()`（全量重算）。输入经 `storage._readKey` 读取（**不用 getAllSiteRules**，避免强制 flush 破坏防抖）。仅新增泛化才写入。
- StorageManager 新增（约 193 行后）：`getGeneralized()`/`addGeneralizedRule(track,rule)`（去重）/`removeGeneralizedRule(track,index)`；均 `_markDirty('pro_blocker_generalized',..)` + `BlockEngine.invalidateCache()` + `applyCSSRules()`。存储 key `pro_blocker_generalized = {domain:[{rule,meta}], path:[{rule,meta}], fused:[{rule,meta,reason}]}`。
- **触发钩子**：`addRule` domainBlock 分支去重后（134 行 applyCSSRules 后）调 `onDomainRuleAdded`；pathPattern 分支 saveData 后（149 行）调 `onPathRuleAdded`。仅这两类触发。
- **合并入匹配引擎**：`getDomainSet`（415）union 泛化 base 域；`getPathMatcher`（426）concat 泛化路径（字面转义、`*`→`.*`）；`PathInvertedIndex.build` 接收合并列表；`applyCSSRules`（650-669）新增泛化域选择器循环（与 domainBlock 并列）。
- `exportAll`（249）+ `importAll`（273 dictKeys）纳入 `pro_blocker_generalized`；import 走特殊非按域合并分支（concat + 去重）。`clearDomain` 不删泛化（跨域），UI 单独提供清除入口。

## 关键风险与缓解

1. **HIGH** `invalidateCache` 漏置 `_cachedPathIndex=null` → 规则编辑后索引过期。Step B 同提交修复。
2. **HIGH** 泛化删除未 invalidateCache+applyCSSRules → 引擎残留陈旧合并规则。Step E 强制调用。
3. **MED** `replaceSync` 单条非法选择器致整表失败 → try/catch 降级 `<style>`+insertRule。
4. **MED** 旧拓扑规则静默失效 → `pro_blocker_topo_hash_version` 迁移清理 + console 提示。
5. **MED** 泛化器误用 getAllSiteRoutes 强制 flush → 改用 `_readKey`。
6. **LOW** adoptedStyleSheets document-start 可用性 → 双 feature-detect + `<style>` 降级。
7. **LOW** LR 仅 hostname 召回下降 → DOM 扫描不受影响，可接受。
