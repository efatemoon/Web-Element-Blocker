管理面板「删除规则撤销」修复与架构审查报告

web-element-blocker.user.js · 修复日期 2026-08-12 · 检测方式：静态深搜 + brooks 严谨审查 + review-and-refactor

一、问题定位

  • 用户报告：管理面板删除规则后「根本没有撤销功能」/ 出现「奇怪的错误提示」。
  • 实测结论：撤销功能确实已实现（showManager → ManagerPanel.call(this) → UIManager._pushUndo / _restoreEntry 链路完整），但存在 致命交互缺陷：
  • 旧 _performUndo() 用 this._undoStack.pop()（全局 LIFO 栈），而每条删除的 Toast 是按时间顺序弹出的。删除 A→删除 B 后，点击 A 的 Toast「撤销」会弹出栈顶 = B，结果恢复了错误的规则。这是用户感知到的「撤销是假的 / 奇怪」的根因。
  • 此外删除前规则快照的捕获逻辑在单条与批量两处重复三分支，可维护性差。

五、架构与代码优化

  • 撤销精确化：用 _restoreEntry(entry) 取代 _performUndo() 的全局 pop()，每条 Toast 绑定自身条目，彻底消除「撤销恢复错误规则」。
  • 幂等保护：新增 entry._restored 标记，重复点击同一 Toast 不会恢复两次。
  • 去重（DRY）：单条删除与批量删除原本各自重复「iframeBlock→global→current→other」三分支快照捕获，统一抽取为 _captureDeletedRule(scope,domain,type,index)，消除约 20 行重复，分支顺序与删除 API 严格一致。
  • 反馈增强：Toast 文案明确「5 秒内可撤销」，撤销成功回显「已撤销删除」。
