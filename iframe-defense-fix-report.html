🖼️ iframe 防线元素拦截修复报告

修复时间：2026-08-12 · 文件：web-element-blocker.user.js

📸 用户反馈（截图还原）

问题 1：面板默认勾选的是「未知 iframe」容器本身，而非帧内广告元素。

问题 2：下方多个 img 广告元素无法批量全选。

问题 3：点击拦截后元素即时消失，但刷新后重复出现——不确定是否真正拦截成功。

🔍 根因定位

优先级 Bug 根因 影响
P0 元素级规则未持久化 blockInFrameNode 里使用 this.storage，但 IframeGuard 对象从未挂载 storage 引用，导致 addRuleForDomain 抛出异常被静默吞掉。 元素只被即时隐藏，刷新后必然复现；用户误以为没拦截成功。
P0 刷新后未自动应用已保存规则 reapplyInFrames() 只在管理面板启用/禁用规则时被调用，init() 中没有在页面加载时应用帧内规则。 即使规则写入了，刷新后也不会自动隐藏帧内广告。
P1 深扫 pathPattern 分支失效 IframeDeepScanner.scanFrame 访问 this.storage.getData()，同样因未注入 storage 而抛异常被 catch，pathPattern 类广告元素漏扫。 部分帧内广告元素无法被检测。
P1 选择器过宽/不够精准 深扫使用 _buildSelector（tag+前两个 class），对图片常为 img；blockInFrameNode 又因已有 selector 跳过了 generateOptimalSelector。 规则既容易误伤其他图片，也可能因过宽而无法精确复现。
P1 预览对内嵌元素无效 document.contains(el) 只对顶层文档有效，iframe 内的元素返回 false，导致预览无法隐藏帧内元素。 用户点「预览效果」对内嵌广告无反馈。
P1 递归嵌套 iframe record 指向父帧 scanFrame 递归调用时把父 iframe 当作第一个参数传入，导致嵌套帧内元素的 record.iframe 错误。 记录与元素实际归属帧不一致，影响后续定位与统计。
UI 默认勾选 iframe 容器 runScan 对 frame 类型也执行 highRisk 默认勾选；unknown iframe 得 50 分被勾选。 用户一打开面板就看到 iframe 被选中，与「要拦截内部广告」的意图冲突。
UI 缺少全选广告元素按钮 工具栏只有「选中高风险/清空」，没有「全选当前列表」。 元素分数 35（中风险）时无法一键批量选中。

🛠️ 修复清单

级别 位置 修复内容
P0 IframeGuard 在对象定义后注入 IframeGuard.storage = StorageService，修复 this.storage undefined 导致的规则静默写入失败。
P0 IframeGuard.init 首次扫描后调用 this.reapplyInFrames()，确保刷新后已保存规则自动生效。
P0 IframeGuard._scanContentIframe 域名封杀后调用 this._applyRulesToDoc(doc, host)，新加载的内容 iframe 也能即时应用历史规则。
P1 IframeDeepScanner 注入 IframeDeepScanner.storage = StorageService，修复 pathPattern 分支读取规则时抛异常。
P1 IframeDeepScanner._buildSelector 优先使用 BlockEngine.generateOptimalSelector 生成精准路径选择器，避免 img 这类过宽选择器。
P1 IframeGuard.blockInFrameNode 强制优先重新生成精准选择器，不再因 rec.selector 已存在而跳过。
P1 IframeGuard.reapplyInFrames 抽取 _applyRulesToDoc(doc, host) 公共方法，被 reapplyInFrames 与 _scanContentIframe 复用，消除重复。
P1 IframePanel.updatePreview 用 el.isConnected 替代 document.contains(el)，使 iframe 内元素预览也能正确隐藏。
P1 IframeDeepScanner.scanFrame 递归扫描嵌套 iframe 时传入 inner 而非父 iframe，修正 record.iframe 归属。
UI IframePanel.runScan 默认勾选仅针对 type === 'element' 的高风险项，iframe 容器不再被默认选中。
UI IframePanel 工具栏 新增「全选当前」按钮，可一键选中列表中所有未拦截元素（含中低风险广告）。
UI IframePanel.collectAll 扫描时若元素已 display:none，显示「已拦截」标签，刷新后也能看到规则生效状态。
UI IframePanel 拦截 Toast Toast 明确区分 iframe 规则与元素规则，并提示「刷新后持续生效」。

📌 用户操作说明

  1. 打开「🖼️ iframe 防线管理」面板。
  2. 列表默认仅勾选帧内高风险广告元素；iframe 容器本身不再被默认勾选。
  3. 如需批量拦截所有列出的广告元素，点击「全选当前」按钮。
  4. 点击红色「🛡️ 拦截选中的 X 个 iframe/元素」按钮，元素会即时隐藏并写入持久规则。
  5. Toast 会提示「X 个元素规则已保存（刷新后持续生效）」。
  6. 刷新页面后，已保存规则会通过 init() → reapplyInFrames() 自动重新隐藏这些元素。
