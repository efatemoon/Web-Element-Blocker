1. 当前架构分析

分层结构

  • ① 菜单调度层：MENU_ITEMS（9 项 [label,title,key]）→ _buildMenu 纯函数 → PanelRegistry（key→UIManager 方法）→ GM_registerMenuCommand。新增面板 = 注册一行 + MENU_ITEMS 加一项，分派逻辑零改动（OCP 接缝良好）。
  • ② 协调器 UIManager：持有 Shadow DOM 宿主 #pro-blocker-ui-host 与全部共享状态（_actionPreview / _globalPreview / _overlayPreview / _iframePreview / _selectionBanner / _previewBanner / _undoStack）；提供 clearPanel()（单一切口清理）、showToast()、_safeCall()、stopSelection()、_freezeNavigation()、_handleClick/_handleTouchEnd、showActionPanel()。
  • ③ 9 个面板函数：SelectionPanel / RegexPanel / GlobalDomainPanel / OverlayScanPanel / ManagerPanel / IframePanel / ExportPanel / AdGuardExportPanel / ImportPanel，均经 XxxPanel.call(this) 注入 UIManager 为 this，行为等价且可独立单测。
  • ④ 服务层：BlockEngine（CSS/正则/结构隐藏）、StorageService（GM 持久化）、EventBus（横切缝）、OverlayService、IframeGuard/Frame*、ContentClassifier、ProtectedCheck、RuleDomain、MessageGuard。
架构本身健康：OCP 接缝、Shadow DOM 隔离、EventBus 解耦均已就位。问题集中在跨面板状态清理的不一致与若干交互/健壮性盲区，而非结构性缺陷。

2. 交互 / 展示 / 逻辑问题归纳

  • 跨面板状态清理不对称（最危险）：clearPanel() 是统一清理入口，但 SelectionPanel 入口只调 stopSelection()，绕过 clearPanel() → 上一个面板的预览隐藏元素在本会话内不恢复、孤儿面板 DOM / 拖拽监听 / 预览横幅残留。
  • 触屏无法进入 iframe 上下文：_handleClick 有"点 iframe 边框进入同源上下文"逻辑，_handleTouchEnd 完全没有 → 移动端无法选中 iframe 内元素。
  • “选中但不可见”：全局域名面板默认勾选 35–39 分域，但"只看广告相关"按 40 分过滤，导致这些域被选却从列表消失。
  • 覆盖层"刷新复活"假象：无 id/class 且无结构选择器时仍即时隐藏元素，但不写持久规则，UI 误导。
  • 误杀排查盲区：影响度评估跳过 structural/complex 规则，最易误杀的高命中规则永远 score=0、不报警。
  • 健壮性：导入不校验规则主键；regex 模式规则缺 mode 字段（依赖隐含约定）；iframe 预览用 document.contains 与 isConnected 口径不一；Toast 容器无上限且被选择横幅遮挡。

3. 优化后架构与前后对比

当前架构（优化前）含 SelectionPanel 绕过 clearPanel 的红色缺陷链路 优化后架构全 9 面板统一经 clearPanel 清理 + 已修复清单

关键架构性改动

  • 单一切口：SelectionPanel 入口由 stopSelection() 改为 clearPanel()，使 9 个面板全部经唯一入口重置共享状态——从"8 面板统一 + 1 面板分叉"收敛为"全统一"。
  • 预览状态机统一：所有 preview（action/global/overlay/iframe）与选择/冻结/横幅，只在 clearPanel() 内还原，消除残留类 bug 的滋生土壤。
  • 触屏 iframe 闭环：_handleTouchEnd 解析真实事件目标（含 iframe 内元素）并在触屏下进入同源 iframe 上下文，对齐鼠标路径。
  • 进口校验：StorageService.importAll 增加各桶主键校验，坏规则不入存储。
